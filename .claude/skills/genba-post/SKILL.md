# ゲンバ投稿（スマホ用）

代表がスマホから投げる短いメモと写真を、そのまま公開できる記事にする。
**質問を減らし、まず完成品を見せる**のがこのスキルの役目。移動中や現場の合間に叩かれる前提で動く。

記事そのものの取り決めは `blog-post` スキルと `aldeco-hp/content/blog.rules.json` に従う。ここは**投稿の段取り**だけを書く。

---

## モードは2つ

### A. 投稿モード（メモが来たとき）

例:「今日は金ヶ崎でブロック積み。雨で段取り変えた」

1. **写真を探す** — チャットに添付されていれば `node tools/photo.mjs recent` で見つかる（添付は `~/.claude/uploads/<セッションID>/` に保存される）。
   PCから `content/inbox/` に置かれた場合は `node tools/photo.mjs list`。
2. **足りない事実を、まとめて1回だけ聞く** — 質問は**最大3つ**。箇条書きで短く。
   スマホで長い往復をさせない。聞くのは記事の核になる数字や固有名だけ。
3. **写真を取り込む** — `node tools/photo.mjs add <slug> <画像パス>`
4. **記事を書く** — `content/posts/YYYY-MM-DD-slug.md`。保存すると自動で検証＋ビルドが走る。
5. **プレビューを送る** — `node tools/preview.mjs <slug>` → SendUserFile で渡す。
6. **OKが出たら公開** — `git add -A && git commit && git push`

### B. 候補モード（ネタを聞かれたとき）

例:「ネタある?」「最近の写真から候補出して」

1. `node tools/photo.mjs list 20` で最近の写真を出す
2. **Read で写真を実際に見る** — 何が写っているかを自分で確認する
3. **記事案を3つ**、それぞれ次の形で提示する
   - 写真（どれを使うか）
   - 仮のタイトル
   - 何を書くか（1行）
   - **本人に確認が必要な事実**（あれば）
4. ユーザーが「2番でGO」と言ったら、投稿モードの3以降に進む

## 絶対に守ること

### 事実は、本人の言葉と写真からしか取らない

数字・日付・工法・場所は**推測で埋めない**。分からなければ、その要素を落とすか聞く。
「たぶん朝7時ごろ」のような曖昧な書き方もしない。書かないほうがマシ。

### 写真は必ず tools/photo.mjs を通す

生のスマホ写真には **EXIF（GPS＝お客様の家の座標）** が入っている。
`photo.mjs` はJPEGを再エンコードしてEXIFを完全に削除する（検証済み）。
`img/` に直接コピーするのは**禁止**。

**この処理はWindows専用**（.NET の System.Drawing を使う）。Linux等の環境では動かないので、
その場合は写真を使わず、文章だけの記事にするか、代表のPCで作業する日に回す。
EXIFを消せないまま公開するのは**絶対にしない**。

### 写真に人・車・表札が写っていないか確認する

Read で見たときに、顔・ナンバープレート・表札・住所の看板が写っていたら、
**公開前に必ず指摘する**。「この写真、右奥に表札が写っています。使いますか？」

### カメラロールは、頼まれたときだけ見る

`カメラ ロール` には家族写真や私的な写真も混ざる。
候補を探すときも**現場写真だけを対象**にし、それ以外の写真については内容に触れない。

### 承認なしに push しない

プレビューを見せて、OKをもらってから。

## どこで動いているかを最初に確かめる

代表は**PCを開かずスマホから投稿したい**。そのため、このリポジトリはクラウド（Linux）で開かれることがある。
環境によってできることが変わるので、**写真を扱う前に必ず確認する**。

```
node tools/photo.mjs doctor
```

| 表示 | できること |
|---|---|
| Windows (.NET WIC) | 縮小・回転補正・メタデータ削除すべて可。JPEG/PNG/HEIC |
| ImageMagick | 同上 |
| Python Pillow | 同上（HEICは不可） |
| ffmpeg | 同上（HEICは不可） |
| 簡易処理 | **位置情報の削除のみ。縮小も回転もできない。JPEGのみ** |

「簡易処理」だったときは、次を守ること。

- **HEICやPNGが来たら受け付けない。** JPEGで送り直してもらう
  （iPhoneは 設定 → カメラ → フォーマット → 「互換性優先」でJPEGになる）
- 回転が必要な写真は警告が出る。**スマホ側で回転させてから送り直してもらう**
- 縮小されないので写真が重い。1記事に使うのは**2枚まで**にする

いずれの環境でも、**位置情報だけは必ず消える**。ここが崩れることはない。

### フックが効かない環境がある

保存時に自動で検証・ビルドが走るのは、フックが読み込まれている環境だけ。
**環境を問わず、プレビューを送る前とpushの前には必ず自分で実行する。**

```
node tools/validate.mjs && node tools/build.mjs
```

## 写真がPCに届く経路

`content/blog.rules.json` の `photos.sources` に定義。上から順に探す。

| 経路 | 探しかた | 使いどころ |
|---|---|---|
| **チャットに添付**（主） | `node tools/photo.mjs recent` | スマホからそのまま送れる。**これが標準**。 |
| 受け取り箱 | `node tools/photo.mjs list` | PCで作業しているとき |

チャットの添付は `~/.claude/uploads/<セッションID>/` に保存されるので、そのまま `photo.mjs add` に渡せる。
`recent` は**直近30分の添付だけ**を見る。過去の添付を全部漁ると現場と無関係な私的ファイルまで拾うため。

**スマホにアプリを入れさせる提案（OneDrive等）はしない。** 添付で完結する。

## メモから記事への膨らませ方

短いメモには、だいたい次が欠けている。**書きながら埋める場所を意識する**。

- **なぜそうしたか** — 「雨で段取り変えた」→ なぜ変える必要があったか、変えないとどうなったか
- **どう判断したか** — アルデコの価値はここ。「当たり前を、因数分解する」が出る場所
- **読者（求職者）にとっての意味** — この現場から、働くとどうなのかが分かるか

メモが本当に一言しかないときは、**無理に長くしない**。
800字に届かないなら、聞くか、その日は書かない。薄い記事は北極星に対してマイナス。

## トーン

代表の声は**演説家型**。熱い宣言・語りかけ・動詞。洒落たコピー職人風の一行は響かない。
きつさは隠さない。盛らない。借り物構文（「地域に根ざした」「アットホームな職場」等）は検証で警告が出る。
