# アルデコのブログを書く

## 北極星（これを外したら書き直し）

> ★ **アルデコに出会う人を、増やし続ける。**
> 指標＝検索とAIからのクリック数（月間）／ 目標値は置かず、**過去最高を超え続ける**。

- 主読者は **求職者・若手**（18〜25歳、未経験・高卒含む）。元請け向け・地域向けは全体の半分未満に抑える。
- 書き手が動かせるのは**入力指標だけ**＝「求職者向け一次情報記事の本数」と「記事あたりの `facts` 数」。
- クリックされるかは**タイトルと description で決まる**。ここを流し書きしない。検索結果で読者が見るのはこの2つだけ。
- ゴール導線は `/recruit/` への遷移。記事末尾のCTAはビルダーが自動で入れるので**本文に書かない**。
- AIに引用されるのは **一次情報だけ**。アルデコにしかない数字・固有名・実体験が1本もない記事は書かない。
- 数字の記録は `node tools/metrics.mjs`。月1で代表が入れる。

## 手順

1. **ネタを決める** — 下の「ネタの4系統」から。迷ったらユーザーに現場の一言を聞く。
2. **事実を確認する** — 知らない数字・日付・手順を**推測で書かない**。分からなければユーザーに聞くか、その要素を落とす。
   材料は `Desktop\会社のゴール\言葉のエッセンス集.md`（実話バンク）と `理念体系_v2.md` から引く。
   **この2ファイルはリポジトリの外（代表のPCのみ）にある。**クラウド等で見つからない環境では、
   実話バンクを参照できないので、事実は必ずユーザーに聞くこと。勝手に思い出して書かない。
3. **書く** — `aldeco-hp/content/_template.md` をコピーして `content/posts/YYYY-MM-DD-slug.md` に保存。
4. **保存すると自動で検証が走る**（PostToolUseフック）。エラーが返ったらその場で直す。全部通るまで繰り返す。
5. **プレビューを見せる** — `node tools/preview.mjs <slug>` でインライン化HTMLを作り、SendUserFileでユーザーに送る。
6. **OKが出てから** `git add -A && git commit && git push`。ユーザーの承認なしにpushしない。

## ネタの4系統

| 系統 | 中身 | 頻度の目安 |
|---|---|---|
| A. 実話 | 金ヶ崎第14期、カーポート工法など、起きたことをそのまま | 月1 |
| B. 現場ログ | ユーザーが送ってきた写真・一言メモから起こす。継続の主燃料 | 週1 |
| C. 疑問回答 | 「外構職人の1日」「未経験でも本当に?」など、検索とAIに拾われる問い | 月1 |
| D. 思想 | 因数分解・目/頭/手・成長の5か条。深さと差別化 | 月1 |

## 言葉の型（`言葉のエッセンス集.md` の「作り方の型」より）

- **数字は説明、コピーは啖呵。** 説明の文で格好つけない。
- **概念より実話の手触り。** 「大切にしています」より「夜11時まで積んだ」。
- **主張には証拠を一発。** 言い切ったら、隣に実話か数字を置く。
- **敵は世間の思い込み。** 職人を流れ弾で撃たない。他社を落とさない。
- **借り物構文を使わない。** 「地域に根ざした」「アットホームな職場」「やりがいのある仕事」は禁止（検証で警告が出る）。
- **スマホで壁を作らない。** 1段落400字まで。
- 代表の声は**演説家型**（熱い宣言・語りかけ・動詞）。洒落たコピー職人風の一行は響かない。

## frontmatter の書き方

必須: `title` `description` `date` `slug` `category` `audience` `author` `summary` `facts` `tags`
任意: `hero` `heroAlt` `faq` `updated` `draft`

- `title` 16〜42字。`description` 60〜120字（検索結果とAIの要約にそのまま出る）。
- `summary` は2〜4行、各12〜70字。**読者とAIが最初に読む要点**。ここだけで内容が分かるように。
- `facts` は1〜6個、各10〜120字。**必ず数字か固有名詞を含める**。これがAIO（AIに引用される力）の核。
- `faq` は各回答30字以上。FAQPage構造化データになって検索結果とAIの回答に直接使われる。
- `category`: 現場 / 働く / 技術 / 思想 / 会社　`audience`: 求職者 / 元請け / 地域

## 本文のルール

- `##` から始める（`#` は記事タイトルが使うので本文では禁止）。`##` は2〜8個。
- 本文800字以上。サイト内リンク1本以上（`/recruit/` `/` `https://genroku.app` など）。
- 画像は必ずalt付き。`![ブロックを積む様子](/img/genba-block.jpg)`
- 使えるのは Markdownサブセットのみ: 見出し・段落・箇条書き・番号リスト・引用・水平線・画像・リンク・`**強調**`・`==マーカー==`・`` `コード` ``。表とコードブロックは非対応。

## 取り決めを変えたいとき

ルールの実体は `aldeco-hp/content/blog.rules.json` にある。**このSKILL.mdではなく、そちらを直す。**
JSONを直すと、生成AIの指針も機械検証も同時に変わる。運用しながらここを育てていくのがこの仕組みの本体。

## やってはいけないこと

- `blog/` 配下のHTMLを手で編集する（次のビルドで消える。正は `content/posts/*.md`）
- 事実を推測で埋める
- ユーザーの承認前に `git push` する
- 検証エラーを残したまま「できました」と報告する
